A retried request is not an edge case. Mobile networks drop responses, load balancers
time out, queue consumers redeliver, and users double-tap buttons. Any endpoint that
changes state will eventually be called twice with the same intent.

Idempotency is the property that lets you stop caring: the second call produces the same
result as the first, and no additional side effects.

## Where this shows up

Payments are the obvious case because the damage is measured in money, but the same shape
appears in signup emails, webhook delivery, order placement, and anything consuming from a
queue with at-least-once semantics.

## What this is not

Idempotency is not the same as retry-safety through locking. A lock prevents concurrent
execution; it does nothing about a retry that arrives ten minutes later. And it is not
deduplication by request body — two genuinely separate payments of the same amount to the
same merchant are a legitimate thing a user can do.
