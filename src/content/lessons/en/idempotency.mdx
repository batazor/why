    title: Claim first, charge second
    narration: >-
      The order matters. Claim the key before calling the bank. Then a duplicate loses

A retried request is not an edge case. Mobile networks drop responses. Load balancers
time out. Queue consumers redeliver. Users double-tap buttons. Any endpoint that changes
state will eventually be called twice with the same intent.

Idempotency is what lets you stop caring. The second call gives the same result as the
first and adds no side effects.

## Where this shows up

Payments are the obvious case, because the damage is measured in money. The same shape
appears in signup emails, webhook delivery, order placement, and anything reading from a
queue with at-least-once delivery.

## What this is not

A lock is not the same thing. It prevents two calls from running at once and does nothing
about a retry that arrives ten minutes later.

Deduplication by request body is not the same thing either. Two separate payments of the
same amount to the same merchant are something a user is allowed to do.
